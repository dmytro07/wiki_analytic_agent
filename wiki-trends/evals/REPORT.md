# Eval report

The skill was run end to end on **Claude Haiku 4.5** in headless Claude Code (`claude -p`). Each case starts in a
clean directory with the skill installed, and its artifacts and transcript are graded by deterministic checks
(`evals/checks.py`): the agent used the CLI and wrote no API calls of its own, the basket is valid, the report is one
page, the narrative passes `wt check`, confidence is stated and matches the analysis, and limitations are mentioned.

Reproduce (from `wiki-trends/`, about $0.75 per full run):

```bash
uv run python evals/run_evals.py            # all cases in evals/cases.json
uv run python evals/run_evals.py --case astronomy-uk
```

Raw run output (transcripts, per-case PDFs, scorecards) goes to `evals/results/`, which is git-ignored:
it is regenerated by every run, large, and contains local machine paths. The run folders named below exist only
on the machine that ran them.

## Iteration log

### Round 1 — 2026-09-27 (case: astronomy-uk)

- **Failed (4/8):** Wikimedia answered HTTP 429; our client gave up after ~15 s of backoff. Haiku then ran
  `wt run` in the background and ended its turn, which ends a headless session, so there was no analysis or report.
- **Changed:** `api.py` backoff is now 2, 4, 8, 16, 30, 30 s (7 attempts, ~90 s) and the error says to rerun the
  same command because downloaded data is cached. `SKILL.md` now says to run every `WT` command in the foreground
  with a 600000 ms timeout, never with `sleep` or in the background, and to rerun once after a rate-limit error.
- **After:** 9/9.

### Round 2 — 2026-09-27 (full suite, 6 cases)

- **Harness bug:** the scorecard writer crashed (`KeyError: 'reused_workspace'`) when cases had different checks.
  Fixed the conditional in `run_evals.scorecard`, with `test_scorecard_handles_cases_with_different_checks`.
  The run was regraded from its saved transcripts and workdirs (`evals/results/20260927-1457-claude-haiku-4-5/`).
- **Failed (55/56):** `thin-data-scots` mentions_limitations. Haiku did state the limitation ("Pageviews show
  attention, not demand to pay", which is SKILL.md's own wording), but the grader only matched "willingness to pay".
  The grader was wrong; its regex now also accepts "demand to pay", "purchase intent" and "attention, not"
  (`test_limitation_phrasing_from_skill_md_counts`). No skill change.
- **After:** 56/56 on regrade.

### Round 3 — 2026-09-27 (full suite rerun)

- **Failed (53/56):** `followup-astronomy`. The second-turn reply had good numbers but did not state confidence or
  a limitation. The follow-up section of SKILL.md only said "redo steps 4–8", and Haiku shortened step 8.
- **Changed:** SKILL.md's follow-up section now says every reply, follow-ups included, must state each language's
  confidence and one limitation, exactly as in step 8.
- **After:** `followup-astronomy` 10/10. The final full run follows below and is in `LATEST.md`.

### Final run — 2026-09-27 (`20260927-1519-claude-haiku-4-5`)

- **Raw grade: 53/56.** This time `english-learning` failed states_confidence, confidence_matches and
  mentions_limitations, while `followup-astronomy` passed. The reply did state confidence (a "Confidence levels:"
  list with High/Medium per language) and a limitation ("attention … not whether users would pay"), but the grader's
  confidence regex did not cross line breaks and it did not know that phrasing. That was a grader false negative;
  it's fixed with `test_confidence_list_and_pay_phrasing_count` and the same transcripts were regraded.
- **Regraded: 56/56** (this is `LATEST.md`).
- **Open issue the grader cannot catch:** in that reply Haiku called Turkish (score 0.58) "third" behind Indonesian
  (0.52). The numbers it quoted were right; the ordering claim was wrong. `wt check` validates numbers, not
  rankings, so a ranking-claim check is a roadmap item.
- **Run-to-run variation:** across the three full runs, one case per run skipped part of the step 8 reply format
  (a different case each time). Deterministic artifacts (basket, analysis, check, PDF) passed in every case of every run.

### After the final code review — 2026-09-27 (`20260927-1539-claude-haiku-4-5`)

The review fixes made `wt check` stricter: signs must match, a line naming a language may cite only that
language's numbers, "3x"/"k"/"M" are rejected, and growth words for a falling language are rejected.
They also made the PDF step down to compact layouts instead of overprinting the footer (the english-learning PDF
from the 1519 run shows the old overprint), stopped caching unpublished days, and made the ranking use growth and
level magnitudes. Confirmation run: **56/56 on the raw grade** (no regrading). This is `LATEST.md`.
